# MTH1W accessibility and usability review evidence

This directory stores **qualified-human accessibility/usability review evidence** for the exact current MTH1W accessibility targets generated by:

```bash
python tools/mth1w_accessibility_review_evidence.py plan --output /tmp/mth1w-accessibility-review-plan.json
```

The current plan has two independent target classes:

- **43 lesson-alternative targets** — each binds the exact authored lesson digest plus the deterministic learner and answer-key Markdown export digests;
- **1 learner-application surface target** — binds the exact current learner-facing Flutter source surface used for Home, curriculum reference, Grade 9 Math learning, draft units, home-learning guidance, and local practice.

A review of a printable Markdown lesson does **not** review the Flutter application. A green Flutter test/build does **not** review a human learner's assistive-technology experience. Both target classes must receive current human approval before the accessibility gate can become eligible for promotion.

## Evidence rules

Each submitted `*.json` file must conform to `schemas/accessibility-review-evidence.v1.schema.json` and must:

- preserve the exact `target_id`, lesson/unit identity, and `target_sha256` from the current generated plan;
- identify the human reviewer and relevant qualification;
- record an offset-aware review timestamp;
- record the actual assistive technologies, devices, document tools, operating systems, or other environments used in `tested_environments`;
- use only the confirmation fields required by that target scope;
- preserve findings, including negative findings, with severity and disposition;
- use `changes-required` or `rejected` when the current surface is not acceptable;
- use `approved` only when every in-scope confirmation is true and there are no open or unresolved major/critical findings;
- keep `attestation_type` equal to `human-accessibility-usability-review`.

Do not edit a generated target digest to make an older judgement apply to changed content. If a lesson, export, or bound learner-app file changes, regenerate the plan and review the new target revision.

## Claim boundary

This evidence system can record qualified-human findings and approvals. It does not itself establish WCAG or AODA legal conformance, Ministry approval, course completion, grade/credit status, or universal usability across every disability, device, assistive technology, language, or context. Those claims require evidence appropriate to their actual scope.
